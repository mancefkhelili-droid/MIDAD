مِداد — إصلاح مفتاح الذكاء الاصطناعي والرصيد الجماعي

ما تغيّر:
1) المستخدم يدخل مفتاح API الخاص به ورابط API واسم النموذج. المفتاح لا يُخزّن في قاعدة بيانات مِداد؛ خيار التذكر يحفظه محليًا في متصفح الجهاز فقط.
2) يجب أن يكون المزوّد متوافقًا مع OpenAI Responses API، لأن طلبات PDF والصور تستخدم تنسيق Responses API. لا يعني ذلك أن كل API عشوائي سيعمل.
3) أزلنا شرط الاشتراك أو امتلاك أكثر من 10 أوراق لدعوة أعضاء الفريق. ما زال حد الفريق 20 عضوًا وحد محاولات رمز الدعوة قائمين.
4) أضفنا مساهمة من محفظة كل عضو إلى صندوق الفريق، مع هدف جمع يحدده صاحب الفريق، وسجل للمساهمات.

التثبيت:
- انسخ index.html وapp.js وstyles.css إلى مشروع Vercel واستبدل الملفات الحالية.
- افتح Supabase SQL Editor وشغّل ملف 20261012_medad_byo_api_team_contributions.sql بعد مراجعة المخطط.
- انشر supabase/functions/medad-ai-document/index.ts باسم medad-ai-document مع Verify JWT مفعّلًا. لا تحتاج OPENAI_API_KEY كسرّ للموقع عند استخدام مفتاح المستخدم. لا تحذف أسرار Supabase الافتراضية.
- جرّب بحسابين: شحن المحفظة، إنشاء فريق، الانضمام، المساهمة، ثم تأكد من خصم رصيد العضو وزيادة صندوق الفريق.

تنبيهات أمنية وتجارية:
- المستخدم مسؤول عن مفتاحه وفاتورته لدى مزوّد الذكاء الاصطناعي. لا تطلب من المستخدم لصق مفتاح لا يثق بمزوّده.
- لا تحفظ المفتاح في localStorage على جهاز عام أو مشترك. المفتاح يُمرر إلى Edge Function أثناء الطلب ولا يُكتب في قاعدة بيانات مِداد أو سجلاتنا عمدًا.
- الصندوق يجمع الأموال فقط في هذا التحديث؛ لم نربطه تلقائيًا بشراء اشتراك من مزود خارجي، لأن ذلك يتطلب تحديد آلية تفعيل الاشتراك والتحقق منها. لا تعرض الصندوق على أنه اشترى الاشتراك تلقائيًا.
- لا يمكن ضمان عمل مزوّد إلا إذا دعم Responses API والملفات/الصور بنفس التنسيق.
